# 制作报价单

使用 `assets/系统报价单模板.xlsx` 作为唯一版式基准。必须同时使用 `spreadsheets` 技能处理工作簿，遵循其导入、渲染、编辑和验证要求。

## 工作流程

1. 提取客户目标、用户角色、业务流程、功能范围、交付边界、端与后台、外部集成、数据迁移、非功能要求和已知约束。
2. 阅读 `references/报价颗粒度与澄清规则.md`，把原始描述整理成可估算、可验收的功能结构。
3. 先形成内部报价草案，再写入 Excel。不要把未经澄清的模糊词直接当作报价条目。
4. 缺失信息会显著改变范围、工期或价格时，提出少量、成组、可直接回答的问题。若用户要求立即报价，采用合理假设并在备注中明确，不要暗中补齐范围。
5. 按模板的“模块—一级模块—说明”三级表达：
   - 模块：稳定的业务域或产品端。
   - 一级模块：用户可感知、可验收的一组能力。
   - 说明：用紧凑的一句话交代对象、关键动作、主要规则或结果。
6. 估算单位、单价和数量。默认单位沿用“人天”；用户未提供单价或定价规则时，不得擅自填写价格，先询问或保留待定并说明。
7. 复制模板后编辑，不得重建或重新设计。保持工作表名称、标题、公司信息区、列顺序、合并关系、颜色、字体、边框、列宽、打印设置、备注区和 6% 税额结构一致。
8. 明细超过模板 15 行时，在总价区之前插入所需行并延续相邻格式、合并、公式和打印区域。不要为了塞进 15 行而过度合并独立业务能力。
9. 保持公式驱动：
   - 每行总价 = 单价 × 数量。
   - 不含税总价 = 明细总价之和。
   - 税额默认 = 不含税总价 × 6%，除非用户指定其他税率。
   - 含税总价 = 不含税总价 + 税额。
10. 填写项目名称、报价日期、项目经理、联系方式、公司地址和服务内容。未知字段留空或标记待确认，不得编造。
11. 在备注中写明对价格有实质影响的范围边界，例如第三方费用、硬件、短信/地图/云资源、数据迁移、驻场、维保期、税率和报价有效期。不要堆砌通用免责声明。
12. 完成前检查：
    - 每个条目仅看名称和说明即可知道交付什么。
    - 相邻条目不存在同义重复、技术层拆分或同一流程的机械切片。
    - 关键角色、端、集成和范围边界未被遗漏。
    - 数量、单价、税额和总价公式可追溯且无错误。
    - 渲染查看全部工作表，确认文字不截断、行高合理、分页和版式未破坏。

## 输出原则

- 默认只交付一份最终 `.xlsx`，文件名使用“项目名-报价单.xlsx”。
- 报价内容使用客户与业务语言；除非技术项本身是独立交付物，不以数据库表、接口、页面控件或代码层作为报价项。
- 同一业务流程下高度关联、由同一角色连续完成的操作优先合并；价值、复杂度、权限、集成或验收标准明显不同的能力应拆开。
- 不为了显得工作量大而增加行数，也不为了显得简洁而把多项独立能力压成“系统管理”“数据处理”等空泛条目。
